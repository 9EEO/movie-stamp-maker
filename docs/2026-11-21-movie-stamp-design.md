# 영화 포스터 우표 메이커 — 설계 문서

작성일: 2026-11-21

## 1. 무엇을, 왜

사용자는 **코닥 미니 3 레트로(P300R, 3×3인치 정사각 인화지)** 로 영화 포스터를 출력한 뒤, **우표 펀칭기**(외곽 31.7 × 38.1mm, 톱니 간격 2.1mm, 톱니 깊이 1.6mm)로 찍어내 **혼자 모으는 영화 우표 컬렉션**을 만든다.

지금은 포스터를 구하고, 우표 크기에 맞게 자르고, 인화지 한 장에 여러 개 배치하는 작업을 손으로 해야 한다. 이 웹앱은 그 과정을 **"영화 검색 → 위치 조정 → 시트 저장 → 코닥 앱 출력"** 으로 줄이고, 이미 만든 우표를 기록해 컬렉션을 관리하게 해준다.

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 폰에서 편하게 (모바일 우선), PC에서도 동작 (반응형)
- 영화 제목 검색으로 포스터를 가져온다
- 인화지 한 장에 우표 3개를 정확한 mm 위치로 배치한 이미지를 만든다
- 출력 대기열이 3개씩 자동으로 시트를 채운다
- 이미 만든 우표 목록을 남기고, 같은 영화를 다시 담으면 알려준다
- 저장 후 코닥 앱으로 바로 넘어간다 (공유 시트)

**비목표**
- 로그인 / 기기 간 동기화 (기기별 저장 + 백업 파일로 대체)
- 판매·대량 생산용 기능, 저작권 처리
- 우표 장식 (액면가, 국가명, 흰 테두리 디자인 등). 포스터가 칼선까지 꽉 찬 직사각형이면 충분하다
- 웹에서 프린터에 블루투스로 직접 출력하기 (코닥 앱을 거친다)
- 다른 프린터나 인화지 크기 지원

**반목표 (기술적으로는 돌아가도 이러면 실패)**
- 출력물 위치가 어긋나서 펀칭했을 때 흰 가장자리가 생기거나 포스터가 엉뚱하게 잘림 → 카트리지 낭비
- 우표 하나 만드는 데 화면을 여러 번 오가야 하는 번거로운 흐름

## 3. 제약 조건

- **주 사용 기기: 안드로이드 폰 + Chrome** (사용자 확인). 이 조합을 기준으로 만들고 테스트한다. PC 브라우저는 보조이며, iOS는 정식 지원 대상이 아니다(동작하면 좋음).

- **인화지:** 76.2 × 76.2mm. 출력 이미지는 **900 × 900px (300dpi, 11.811px/mm)** 기준으로 만든다. *(프린터 해상도와 코닥 앱의 크기 조정 방식은 실측 전이라 확정되지 않았다. 6장의 보정 기능으로 대응한다.)*
- **우표 칼선(외곽):** 31.7 × 38.1mm
- **번짐 여유(bleed):** 칼선 바깥으로 사방 **1mm**씩 포스터를 더 그린다 (사용자 결정). 펀칭이 조금 어긋나도 흰 가장자리가 생기지 않게 하기 위함이다. 맞춤용 가이드 선은 넣지 않는다.
- **시트당 3개 배치 (사용자가 실제로 펀칭해 본 배치):** 세로 2개(위) + 가로 1개(아래)

### 시트 레이아웃 (칼선 기준, 단위 mm, 원점은 인화지 왼쪽 위)

| 칸 | 방향 | x | y | 너비 | 높이 |
|---|---|---|---|---|---|
| 1 | 세로 | 4.267 | 2.133 | 31.7 | 38.1 |
| 2 | 세로 | 40.233 | 2.133 | 31.7 | 38.1 |
| 3 | 가로 | 19.05 | 42.367 | 38.1 | 31.7 |

- 가로 여유 12.8mm를 3등분(4.267mm)하고, 세로 여유 6.4mm를 3등분(2.133mm)했다.
- 1mm 번짐을 더해도 칸 사이가 겹치지 않는다(세로 틈 2.133mm ≥ 1 + 1mm).
- 3번 칸을 가운데 정렬한 것은 내 판단이다. 레이아웃 값은 코드 상수 한 곳에 모아 두어 쉽게 바꿀 수 있게 한다.
- **3번 칸(가로)에는 포스터를 시계 방향 90° 돌려서 넣는다.** 펀칭한 뒤 돌려 보면 1·2번과 같은 세로 우표가 된다. 사용자에게는 모든 우표가 같은 세로 형태로 보이고 다뤄진다. 회전은 시트 이미지를 만들 때만 적용한다.

## 4. 만드는 방법 — 검토한 대안

| 대안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **1. 설치형 웹앱(PWA) — 선택** | 정적 사이트. 브라우저 안에서 캔버스로 시트 이미지를 만들고, 컬렉션은 IndexedDB에 저장. TMDB는 사용자가 설정에 넣은 키로 브라우저에서 직접 호출 | 서버 없음·유지비 0원, 폰 홈 화면에 설치, PC도 같은 주소로 사용 | 처음 한 번 TMDB 키 입력 필요 |
| 2. PWA + 중계 서버 | TMDB 키를 서버에 숨김 | 키 입력 불필요 | 서버 관리 부담. 1인 사용이라 이득이 작음 |
| 3. 네이티브 앱 | 안드로이드/iOS 앱 | 코닥 앱 연동이 조금 더 매끄러울 수 있음 | PC 불가, 개발·설치 부담이 큼 |

사용자가 **1번**을 선택했다.

## 5. 화면과 흐름 (사용자 결정: "컬렉션 + 대기열(C) 구조에 큰 조정 화면(B)")

```
[내 컬렉션] 홈
 ├ 🔍 영화 검색 → 결과 탭 → "출력 대기"에 추가
 │      └ 곧바로 [조정 화면] 열림 (전체 화면)
 ├ 출력 대기: 3개씩 자동으로 시트에 채워 미리보기 (실제 mm 비율)
 │      ├ 시트 속 우표 탭 → 조정 화면 다시 열기
 │      └ [시트 저장/공유] → 900×900 PNG → 공유 시트(코닥 앱) / 다운로드
 ├ 만든 우표: 저장한 우표들의 갤러리
 └ 설정: TMDB 키, 출력 보정, 백업 내보내기/가져오기
```

### 5.1 검색과 추가
- TMDB `search/movie`를 `language=ko-KR`로 호출해 한국어 제목과 포스터를 우선 보여준다.
- 결과 항목: 포스터 썸네일, 제목, 개봉 연도.
- 이미 대기열이나 만든 우표에 있는 영화(TMDB id 기준)면 **"이미 있음"** 배지를 붙인다. 막지는 않는다 (같은 영화를 다른 포스터로 또 만들 수 있다).
- **포스터 고르기:** 조정 화면에서 해당 영화의 다른 포스터(TMDB `movie/{id}/images`, 한국어·원어·언어 없음)를 가로 스크롤로 골라 바꿀 수 있다.
- **내 사진 올리기:** 검색 대신 직접 이미지를 올려서 추가할 수 있다. 제목은 직접 입력하고, TMDB 키가 없어도 동작한다.

### 5.2 조정 화면 (B식 큰 화면)
- 화면 가운데에 **우표 틀**(칼선 31.7×38.1 비율)을 크게 보여준다. 바깥은 어둡게 처리하고, 1mm 번짐 영역은 점선으로 표시한다.
- 포스터는 틀 뒤에서 **드래그로 이동, 핀치(PC는 휠/슬라이더)로 확대**한다.
- **[꽉 채우기 | 전체 보이기]** 전환
  - 꽉 채우기(기본): 번짐 영역까지 빈틈없이 덮는 최소 배율로, 가운데 정렬한다. 이 배율보다 작게 줄이지 못하게 막는다.
  - 전체 보이기: 포스터 전체가 칼선 안에 들어가고, 남는 부분은 흰색이다.
- 저장되는 값: 포스터 기준 정규화된 크롭 정보(중심 x/y, 배율). 화면 크기와 무관하게 다시 그릴 수 있어야 한다.
- 담자마자 이 화면이 열리지만, [완료]만 눌러도 기본값(꽉 채우기·가운데)으로 저장된다.

### 5.3 출력 대기열과 시트
- 대기열 순서대로 3개씩 시트 1, 2, …에 자동으로 채운다.
- 순서는 길게 눌러 드래그해서 바꾼다. 우표를 대기열에서 빼거나 지울 수 있다.
- 3개가 안 된 시트도 저장할 수 있고, 빈 칸은 흰색이다.
- **[공유] / [저장] 두 버튼을 나란히 둔다** (내 판단: 코닥 앱이 안드로이드 공유 목록에 뜨는지 아직 실측하지 않았으므로 두 경로를 모두 제공).
  - [공유]: Web Share API(파일 공유)로 공유 시트를 열어 코닥 앱을 고르게 한다. 안드로이드 Chrome에서는 탭한 뒤 PNG를 만들어도 된다. 지원하지 않는 브라우저에서는 이 버튼을 숨긴다.
  - [저장]: PNG를 다운로드한다. 안드로이드에서는 갤러리/다운로드 폴더에 들어가고, 코닥 앱에서 불러온다.
  - 첫 출력 때 사용자가 어느 경로가 됐는지 확인하면, 이후 그 버튼을 주 버튼으로 강조한다(설정에서 변경 가능).
  - 시트를 여러 장 저장할 때는 장마다 버튼을 따로 둔다. 코닥 앱은 한 번에 한 장씩 출력하는 흐름이라 그렇게 했다.
- 저장/공유 버튼을 누르는 순간 그 시트의 우표들을 **"만든 우표"로 옮긴다.** 실제 출력 여부는 알 수 없기 때문이다. 대신 실행 취소 토스트를 띄우고, 만든 우표에서 [다시 대기열로] 보낼 수도 있다.

### 5.4 만든 우표 (컬렉션)
- 우표 모양 썸네일 그리드로 보여준다. 최신순이 기본이고, 제목 검색을 지원한다.
- 우표를 탭하면 상세 화면: 영화 제목, 연도, 만든 날짜, [다시 만들기(대기열에 복사)], [삭제].

### 5.5 설정
- **TMDB API 키**(v4 읽기 토큰 또는 v3 키) 입력. 발급 방법을 짧게 안내하고 링크를 단다. 키는 IndexedDB나 localStorage에만 저장한다.
- **출력 보정 (6장)**
- **백업:** 전체 컬렉션(대기열·만든 우표·크롭값·직접 올린 이미지·보정값)을 JSON 파일 하나로 내보내고 가져온다. TMDB 포스터는 경로만 저장하고 가져올 때 다시 받는다. 가져오기는 "합치기"를 기본으로 하고, TMDB id와 생성 시각으로 중복을 거른다.

## 6. 출력 보정 (가장 큰 위험 대응)

코닥 앱이 이미지를 그대로 출력하는지, 확대하거나 잘라내는지는 아직 모른다. 이게 어긋나면 모든 출력이 틀어진다.

- **보정용 테스트 시트**를 만든다. 3칸의 칼선 외곽선, 각 칸 중심 십자 표시, 50mm 눈금자(가로·세로), 인화지 가장자리에서 2mm 안쪽 선을 그린다.
- 사용자가 테스트 시트를 출력해 자로 재거나 펀칭기를 대어 본 뒤, 설정에 **배율(%)과 가로·세로 오프셋(mm)** 을 입력한다. 이후 모든 시트 이미지에 이 값을 적용한다.
- 처음 시트를 저장하려 할 때 보정을 안 했으면 "테스트 시트를 먼저 출력해 보세요"라고 한 번 안내한다. 건너뛸 수도 있다.
- 사용 안내: 코닥 앱에서 **테두리 없음(borderless)** 모드로 출력하고, 코닥 앱의 자르기/위치 편집은 건드리지 말라고 알려준다. *(코닥 앱 실제 옵션 이름은 구현 시 확인)*
- 보정 모델은 "배율 + 오프셋"이다. 코닥 앱이 출력할 때마다 다르게 잘라낸다면 이 모델로는 부족하다. 이 경우는 테스트 시트로 드러나며, 그때 다시 설계한다.
- 배율 보정은 인화지 중심 기준으로 적용하고, 테스트 시트에도 보정값을 적용한다(보정 후 재확인용).

## 7. 기술 결정 (내 판단, 사용자에게 고지)

- **스택:** Vite + TypeScript + Preact(가벼운 UI 라이브러리). 번들이 작아 폰에서 빠르다.
- **저장소:** IndexedDB (`idb` 같은 얇은 래퍼). 직접 올린 이미지는 Blob으로 저장한다. 첫 실행 때 `navigator.storage.persist()`를 요청해 브라우저가 데이터를 지우지 않게 하고, 홈 화면 설치를 한 번 권한다.
- **이미지 생성:** `<canvas>` 900×900에 그리고 PNG로 내보낸다. 보정값을 적용한다.
- **포스터 이미지:** `image.tmdb.org`에서 받는다. 캔버스로 내보내려면 CORS가 허용돼야 한다(`crossOrigin="anonymous"`). **구현 첫 단계에서 확인**하고, 막히면 fetch → Blob → objectURL로 우회한다. 출력용으로는 큰 해상도(`w780` 이상 또는 `original`)를 쓴다.
- **PWA:** manifest + service worker. 앱 화면 리소스는 오프라인 캐시한다. 검색에는 네트워크가 필요하다.
- **호스팅:** GitHub Pages 같은 무료 정적 호스팅
- **언어:** UI는 한국어

## 8. 빌더에게 맡기는 것

- 시각 디자인 세부(색, 폰트, 아이콘). 단, 우표 썸네일은 톱니 모양 마스크로 우표처럼 보이게 한다.
- 컴포넌트 구조, 상태 관리 방식
- 정확한 DB 스키마 (최소 필드: id, 출처(tmdb/upload), tmdbId, 제목, 연도, 포스터 경로 또는 Blob 참조, 크롭값, 상태(queued/made), 대기열 순서, 생성 시각, 만든 시각)
- 테스트 범위. 단, **시트 레이아웃 좌표 계산과 크롭 → 캔버스 변환은 단위 테스트 필수**다(mm·px 정확도가 핵심이므로).
