# 전체 보이기 여백 색 — 짧은 설계

## 왜

전체 보이기(fit)로 담으면 포스터 옆에 남는 여백이 항상 흰색이라 우표가 비어 보인다. 여백을 포스터와 어울리는 색으로 채우고 싶다.

## 목표 / 하지 않는 것

- 목표: 우표마다 여백 색을 정한다. 대부분은 추천 칩 하나로 끝나고, 원하는 색이 없으면 스포이드나 색 고르기로 정한다.
- 하지 않는 것: 흐린 포스터로 여백 채우기, 그라데이션, 시트 전체 배경색.
- 실패로 보는 것: 이미 만든 우표의 출력 모습이 사용자가 손대지 않았는데 바뀌는 것.

## 방법 (고른 것: 1)

1. **추천 색 + 스포이드 + 직접 고르기** — 고름. 대부분 한 번 탭으로 끝나고, 원하는 색이 없을 때도 길이 있다.
2. 흐린 포스터로 채우기 — 고르지 않음. 색을 고를 필요는 없지만, 우표 크기로 인화하면 탁해 보일 수 있다.
3. 색 고르기 창만 — 고르지 않음. 폰에서 포스터에 맞는 색을 직접 찾기 어렵다.

## 설계

- **데이터**: `Crop`에 선택 항목 `bg?: string`(`#rrggbb`)을 더한다. 값이 없으면 흰색이다. 그래서 기존 우표와 백업은 그대로 흰색이다. 백업을 가져올 때 `bg`가 있으면 `#rrggbb` 형식인지 검사한다.
- **그리기**: 시트 출력, 조정 화면 미리보기, 썸네일(만든 우표) 모두 여백을 `crop.bg ?? 흰색`으로 칠한다. 꽉 채우기에서는 여백이 없으니 영향이 없다. `bg`는 모드를 바꿔도 남아 있어서, 다시 전체 보이기로 오면 그 색이 돌아온다.
- **기본값**: 조정 화면에서 전체 보이기로 처음 바꿀 때(`bg`가 없을 때) 가장자리 색을 자동으로 넣는다. 이미 전체 보이기로 저장된 우표는 열어도 바꾸지 않는다.
- **추천 색** (`src/core/palette.ts`, 픽셀 배열을 받는 순수 함수라 테스트 가능):
  - 가장자리 색: 여백이 생기는 두 변(포스터가 우표보다 세로로 길면 좌우 열, 아니면 위아래 행)의 평균색.
  - 포스터 색 3개: 이미지를 작게 줄여 색을 묶은 뒤 많이 쓰인 순서로 뽑는다. 서로, 그리고 가장자리 색과 너무 비슷한 색은 건너뛴다.
- **조정 화면 UI**: 전체 보이기일 때만 모드 버튼 아래에 한 줄이 보인다.
  `여백 [흰색] [가장자리] [색1] [색2] [색3] [🎯 스포이드] [🎨 직접]`
  - 칩은 색 동그라미이고, 고른 칩이 표시된다(`aria-pressed`). 이름은 aria-label로 붙인다.
  - 🎯: 누르면 스포이드 상태가 되고("포스터를 눌러 색을 고르세요"), 미리보기를 한 번 탭하면 원본 이미지에서 그 지점 색을 읽어 넣고 끝난다. 그동안 끌기·확대는 막는다. 포스터 밖을 탭하면 아무것도 하지 않는다.
  - 🎨: `<input type="color">`. 안드로이드 Chrome 기본 색 선택기가 열린다.
  - 안드로이드 Chrome에는 EyeDropper API가 없어서 스포이드는 직접 만든다.
- **만드는 사람이 정할 것**: 칩 크기·모양, 색 묶음 방식과 "비슷함" 기준값, 추천 색 계산 시점(이미지를 불러올 때 한 번).
